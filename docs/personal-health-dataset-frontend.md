# Mac 前端适配：个人健康数据集

服务器后端是数据治理和指标口径的唯一实现位置。前端负责补录、展示和研究交互。API 契约及接入见 [个人健康数据集文档](personal-health-dataset.md)。

微信小程序的分批实施、浏览器授权返回流程和专用 Mac Prompt 见 [小程序适配说明](personal-health-dataset-miniprogram.md)。

## 页面与交互

当前线上网页缺少 Oura 设置入口，需先补一个 Oura 连接卡片：使用现有登录 JWT 调用 `GET /api/v1/oura/status` 显示状态，`GET /api/v1/oura/auth-url` 获取并在浏览器打开 auth_url。完成授权后回到应用刷新状态，并允许调用 `POST /api/v1/oura/sync` 同步。授权失效时提供“重新连接”；不要把固定授权链接、档案关联 state 或服务密钥写死到前端。

1. **数据目录 / 数据质量**：展示 catalog 的类别、数量、记录日期范围、设备能力、最后同步时间、研究 dirty_days。空值展示“暂无记录”，渠道不可用与无记录分别提示。
2. **健康日志**：测量、体检、用药、补剂、症状、生活事件、饮食完整确认。使用已有登录 JWT 调用 POST journal；禁用上传未来事实。一次操作生成一次 external_id，网络重试复用。
3. **每日档案 / 时间线**：读取 days 和 records，展示每日指标、来源、估算方式、记录覆盖、事件、缺失媒体。默认选择近期窗口；指标名称和单位取自 catalog，避免在前端再计算不同口径的汇总。
4. **研究页**：先选择假设指标 x/y、日期范围和 lag。绘制时间线/日对散点，展示 pairs、expected_pairs、pearson_r 与状态。不能将相关性渲染为健康诊断或因果结论。

本轮页面可以分批实现，优先补录与数据质量；不要求同时重做原营养、睡眠和运动页面。

## 必须遵循的接口规则

- 前端用已有登录 JWT 读取 research 路由及写 journal。**不要在浏览器 bundle、Vite 环境变量或小程序源码中嵌入 MCP_API_KEY。**外部 agent 的服务密钥单独放在该客户端的私有认证配置。
- 时间使用带时区 ISO 8601，如 `2026-10-11T08:00:00+08:00`。明确当前界面日期属于发生日还是起床日。
- 已知测量的 code 和单位遵循后端定义；单位转换显式执行并注明，不能用改标签代替换算。其他体检 code 必须带明确单位，历史明细通过 journal 查询。
- `null` 与 0 严格区分。数值为 0 时显示 0；null 显示未知。已有营养合计只标“已记录摄入”。
- `stale=true` 显示“整理中”，避免作为正式统计；`materialized=false` 显示“尚未整理”，不补空数据为零。
- 当天 quality.partial_day 为 true，趋势对比提示“今天尚未完成”；恢复指标虽可用于当日指导，不能默认混入完整行为日统计。
- 保存 journal 收到 201 即成功，research_status=queued 表示后端将整理。不要因研究重算尚未结束而重传记录。
- 修改日志时使用新 external_id + 当前记录 supersedes_id；409 提示刷新当前版本；不要覆盖或删除旧日志。
- 用户确认全天摄入完整前，明确涵盖零食、饮料等；补录/修改/删除当天餐食后后端会自动使旧确认失效，前端撤去已确认提示并刷新数据、提醒重新确认。用户主动撤销确认时提交 complete=false。
- 大心率/睡眠阶段/运动采样只在用户展开时请求 include_samples=true；遵循 next_offset 分页，每页不超过25条。不自动拉取全部历史大序列。
- 媒体原图缺失显示占位；不得用 AI 图冒充原照片。签名 URL 过期沿用现有媒体刷新流程。
- 本地开发跨域沿用已有代理配置或由后端部署配置允许准确的 Mac 开发 origin；不要关闭认证或使用任意 Origin。

## 可复制给 Mac 前端 agent 的 prompt

```text
请在我的 Mac 本地健康项目前端实现“个人健康数据集 / 个人健康数据云服务”的前端适配。
后端已经提供 /api/v1/research，请先阅读服务器给出的 personal-health-dataset.md
和 personal-health-dataset-frontend.md；后端数据结构和指标口径以该契约和 catalog 为准。

优先实现：
0. Oura 连接管理入口：线上网页目前没有设置入口。用现有登录 JWT 调用
   GET /api/v1/oura/status、GET /api/v1/oura/auth-url；打开返回的 auth_url，
   授权回调完成后刷新连接状态，再用 POST /api/v1/oura/sync 同步。处理授权失效和重新连接。
1. 数据目录与质量：调用 GET /catalog，展示数据类别、记录量、日期范围、能力/同步状态、dirty_days。
2. 结构化健康日志：调用 POST /journal，支持体重/血压等测量、体检、用药/补剂、症状、生活事件、
   饮食全天记录完整确认。使用现有登录 JWT，带时区时间；一次保存操作生成一个 external_id，重试复用。
3. 每日档案与时间线：调用 GET /days 和 GET /records/{dataset}，支持指标筛选、日期窗口、分页和来源查看。
4. 基础研究页：调用 GET /patterns，选择 x/y、日期窗口、lag=0..14，展示有效日对与探索性相关。

重要约束：
- 用已有主用户登录 JWT 访问 research 读写接口，不把外部服务 MCP_API_KEY 放进前端。
- 不改后端，不在前端重复实现数据治理、跨设备去重或研究指标算法。
- null 不等于0；缺失训练不等于休息；照片营养为估算且只覆盖已记录餐食。
- stale/materialized/partial_day 必须体现；不要把未完成日与完整日直接比较。
- 饮食完整确认需明确用户确认；补录/修改/删除餐食后撤去确认提示、刷新数据并提醒重新确认，后端自动使旧确认失效。
- 日志修正使用新 external_id 和当前 supersedes_id，保留版本链。
- 只在展开时读取大采样，遵循分页，不自动加载全部心率历史。
- Pattern 是研究线索，显示样本量、方向与数据缺口，不渲染为因果、诊断或医学健康评分。

先检查项目现有 API client、登录状态、页面导航和组件风格，做小范围集成。
完成后在 Mac 本地验证保存/重试/修正、日期边界、空值与零值、整理状态、分页和移动端布局。
```
