Health 微信小程序 · 前端架构

基于 v0.3.12 代码梳理 · 页面层、应用运行时、请求缓存、媒体链路与后端服务边界

前端职责

  • • 六个页面围绕统一请求层获取业务数据
  • • App Runtime 负责登录恢复、通知刷新和预加载
  • • 页面把后端响应归一化为稳定视图模型
  • • 微信原生能力处理图片上传、下载与相册保存

数据与性能

  • • GET 请求按接口 TTL 缓存并复用在途 Promise
  • • 状态轮询绕过缓存，完成后强制刷新详情
  • • Token、本地刷新标记与坏图熔断保存在客户端
  • • 签名 URL 保留原始 query，避免破坏鉴权参数

关键边界

  • • 小程序只负责展示与交互，不参与海报内部排版
  • • 核心识图与异步未来三餐建议是两个独立状态
  • • 业务数据库、AI、设备 API 与对象存储位于后端侧
  • • 后端部署不属于本小程序仓库的发布范围
