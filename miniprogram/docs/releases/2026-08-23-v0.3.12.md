# Mini Program 0.3.12

## Summary

This release fixes nutrition photo uploads that were rejected before image recognition because the mini program sent an ISO UTC timestamp while the backend expects local `YYYY-MM-DD HH:mm` multipart input. It also restores visible daily nutrition progress and makes future meal recommendations easier to distinguish.

## Upload behavior

- Meal uploads now send local device time such as `2026-08-23 09:05`.
- The mini program no longer converts the selected meal time to UTC with `toISOString()`.
- Explicit upload timestamps and request-layer defaults share the same formatter.
- Image compression, the 120-second upload timeout, duplicate-submission protection, timeout recovery, and asynchronous recommendation polling are unchanged.

## Nutrition UI

- Future breakfast, lunch, dinner, and snack recommendations use distinct meal-specific symbols and restrained active-state colors.
- English backend meal types are normalized alongside Chinese labels, with recommendation order used only as a compatibility fallback.
- Partial-day summaries continue to show recorded calorie and macro progress instead of hiding their rings and bars.
- Calorie, protein, carbohydrate, and fat cards display their current reference percentages directly.
