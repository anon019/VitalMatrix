# v0.3.0 Release Notes

Release date: 2026-08-21

## Summary

This release adapts the mini program to the optimized profile, nutrition analysis, AI recommendation, and poster-generation contracts while retaining the established online visual language.

## Highlights

- User profile fields now come from and update through `/api/v1/user/profile`.
- Login now exchanges `wx.login()` codes through `/api/v1/auth/wechat-login`; business requests continue to use the returned Bearer token.
- Signed meal and poster media URLs are resolved without parsing or reordering their query strings and are refreshed at most once after expiry.
- Today prioritizes recorded nutrition and AI actions before recovery/activity detail, with each Oura metric showing its own source date.
- Trends include calories, protein, carbohydrates, fat, and meal count; averages exclude unrecorded dates.
- The existing settings page is now available from the main tab bar.
- Meal uploads and detail entry never generate a poster. Posters are requested only after the user taps **生成精美海报**.
- Poster previews scroll from top to bottom, keep actions above the safe area, and verify downloaded image dimensions before saving.
- Nutrition details lead with the photo, calorie range, four nutrition metrics, score, conclusion, and confidence.
- Confirmation questions and uncertainty notes are separated from long-form analysis.
- Health insights default to two strengths and two improvements; the full list and recipe steps are expandable.
- Next-meal recommendations use `next_meal_recipes` and show one menu based on the latest seven days.
- AI guidance is ordered as nutrition, sleep recovery, activity training, and health knowledge, with the real backend model and generation time.

## Compatibility

- Older meals without calorie ranges fall back to their single calorie estimate.
- Older records may still use `next_meal_recipe` or `next_meal_tips`; removed `next_meals` and `next_meal_menu` are no longer read.
- Missing analysis-quality fields render a neutral confidence state instead of failing the page.

## Versioning

- App version: `0.3.0`
- Recommended Git tag: `miniprogram-v0.3.0`

## Verification

- JavaScript syntax, JSON parsing, WXML paired-tag counts, request-contract tests, deprecated-field searches, and repository diff checks passed locally.
- WeChat DevTools passed on iPhone 15 Pro Max and iPhone 6/7/8 simulators for Today, Nutrition, Detail, AI, Trends, and poster preview layouts.
- The cached poster path issued one POST, reopened without another POST, required confirmation before force regeneration, scrolled to the verified footer, and saved an undistorted `1792×2400` PNG.
- Executable mocks passed the single-refresh 403 recovery and denied-album-permission guidance paths.
- A physical phone is still required to confirm the real WeChat album permission/settings round trip and friend-sharing card. The live backend returned a cached poster, so uncached 30–60 second generation latency was not exercised.
- Some historical signed meal-image URLs refresh correctly but still return 404 because the corresponding backend objects are missing; the UI now falls back to placeholders without retry loops.
