# Mini Program 0.3.15

## Changes

Meal list and detail parsing now reads `ai_analysis`, including nutrition scores, identified foods, and all future-menu recipes. Existing recipe fields and signed media query parameters are preserved. Image-analysis metadata comes from `current_ai_model`; poster and AI recommendation models remain response-driven.

Meal list and detail requests bypass the GET cache. Upload results appear first immediately, and recommendation completion retains its forced detail refresh. A one-time migration clears known business cache keys without deleting authentication or pending image drafts.

## Performance and resilience

- Deduplicate cold concurrent GETs and prevent invalidated requests from repopulating caches.
- Encode cache parameters to prevent ambiguous keys.
- Serialize meal pagination, discard stale pagination after refresh/upload, and append only new rows through `setData`.
- Preserve existing nutrition data on refresh failure, offer retry, and only record successful refresh times.
- Refresh the nutrition date on page reentry and accept numeric nutrient strings.
- Remove unused full AI payloads from view state and normalize recommendations once per load.

- Retain bounded polling retries when a completed recommendation cannot yet be refreshed, together with the public repository's contract tests.
