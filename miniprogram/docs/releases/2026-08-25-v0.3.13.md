# Mini Program 0.3.13

## Summary

This release restores a real seven-day visualization for nutrition trends and restores the personal mini program's fixed-user data connection. The health data remained on the backend; a prior switch to WeChat identity had mapped the client to a new empty user.

## Fixed-user data connection

- Startup uses `wx.login` and `POST /api/v1/auth/miniprogram-login`, opening directly into the backend-mapped fixed personal dataset without a password UI.
- Auth storage v2 clears legacy token, user, auth-mode, and known empty business caches once while preserving unrelated storage and pending image drafts.
- Token, expiry, auth mode, and login time are written as one session object; valid `fixed_miniprogram` sessions are reused until near expiry.
- Concurrent pages share one authentication Promise, and concurrent business 401 responses share one refresh lock before each request is replayed at most once.
- The login/logout concept is removed from the user-facing settings flow; the bearer token remains an internal API transport detail.
- Authentication failures show a concise retry state; 403 and non-auth server errors never start a login loop.

## Nutrition trends

- Calories, protein, carbohydrates, fat, and recorded meals each use an independent seven-day bar chart.
- Each bar keeps its value, weekday, and date visible without hover or extra interaction.
- Card headers retain recorded-day averages and state the number of actual record days.
- Missing days render as explicit `--` states instead of zero-value bars.
- Every metric uses a stable reference scale for the full week and expands to a rounded ceiling only when a real value exceeds that reference.
- Full-height gray tracks are removed; the colored bar itself is the only height encoding.
- Existing nutrition colors and direct labels remain available for mobile readability.

## Nutrition detail and rendering performance

- Health insights render every backend item directly. There is no truncation, hidden remainder, or expand/collapse interaction.
- Meal history and detail pages send only template-facing fields through `setData`, avoiding repeated serialization of full AI responses and recipe collections.
- Developer logs retain request paths and status codes while omitting complete health-response payloads.
- Settings no longer presents fallback defaults as though they were server data when the profile request fails.
- Today-page inline styles now bind already-normalized numbers directly, removing 30 false CSS diagnostics without changing rendered values.
