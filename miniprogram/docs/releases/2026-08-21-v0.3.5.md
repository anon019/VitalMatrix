# v0.3.5 Release Notes

Release date: 2026-08-21

## Summary

This release fixes the future-meal recommendation layout and makes incomplete recipe responses honest and readable.

## Highlights

- Breakfast, lunch, and dinner use concise labeled tabs with distinct icons and calories.
- Full menu names now appear inside the selected card where they can wrap naturally.
- Recommended dishes display the portion and protein values already returned by the backend.
- Empty ingredient, cooking-step, and health-benefit rows are no longer rendered.
- Missing recipe detail is shown as an explicit availability message instead of blank labels.
- Compatible aliases such as `ingredient_list`, `materials`, `instructions`, and `directions` are supported for future backend responses.

## Backend Contract Finding

The verified dinner response returned `name`, `portion`, `protein`, and `calories` for every dish, but did not return `ingredients`, `cooking_steps`, `health_benefit`, or `cooking_time`. The frontend can therefore show the available nutrition and portion data, but the backend must add those fields before complete recipes can be displayed.

## Verification

- JavaScript syntax and `git diff --check` passed.
- WeChat DevTools recompiled the real dinner detail without build errors or workspace problems.
- Breakfast, lunch, and dinner tabs rendered clearly and the lunch interaction changed the selected menu.
- Portion, protein, and the missing-detail state rendered correctly for the real dinner recommendations.

## Versioning

- App version: `0.3.5`
- Recommended Git tag: `miniprogram-v0.3.5`
