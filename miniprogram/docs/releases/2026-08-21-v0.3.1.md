# v0.3.1 Release Notes

Release date: 2026-08-21

## Summary

This release aligns the nutrition detail experience with the latest backend meal-plan and poster contracts while keeping implementation details out of the consumer UI.

## Highlights

- Follow-up recommendations no longer stop at the first recipe. Every backend-provided meal is available through a compact switcher.
- Meal names remain backend-driven, including lunch, dinner, snack, or next-day meals.
- The nutrition list and detail page no longer expose model names, legacy labels, or analysis-upgrade controls.
- The top conclusion is presented as a concise meal brief; detailed findings and actions remain in their dedicated sections.
- Compatible dish calorie, name, preparation, ingredient, step, and benefit fields are normalized. Missing dish calories are omitted rather than shown as zero.
- Poster preview copy is user-facing and retains only the latest/cached status plus backend-verified nutrition values.

## Compatibility

- Single-object `next_meal_recipe` and simple `next_meal_tips` responses remain supported.
- Older dish field names remain readable alongside the latest aliases.
- The frontend does not synthesize or rename meal types when the backend changes the third recommendation.

## Versioning

- App version: `0.3.1`
- Recommended Git tag: `miniprogram-v0.3.1`

## Verification

- JavaScript syntax and repository diff checks passed locally.
- WeChat DevTools compiled the project and loaded live nutrition data for the latest meal.
