# v0.3.3 Release Notes

Release date: 2026-08-21

## Summary

This release adapts meal photo capture to the backend's two-stage nutrition pipeline: core recognition is shown immediately, while future-diet recommendations continue independently in the background.

## Highlights

- Uploading, image recognition, and core meal analysis use one guarded submission state and end as soon as `POST /api/v1/nutrition/upload` returns.
- Recommendation generation is represented inside the future-24-hour recommendation card and never blocks the completed meal analysis.
- Pending recommendations are checked every two seconds. Polling stops on completion, failure, page hide/unload, or after 90 seconds.
- A failed recommendation can be retried through the recommendation endpoint without re-uploading the image. `force=true` is reserved for an explicitly confirmed regeneration.
- Client upload timeouts refresh recent meal records before showing an error, preventing accidental duplicate meals when the server completed after the client stopped waiting.
- Confirmation questions are removed. Confidence, portion assumptions, and uncertainty notes remain as read-only analysis context.
- Legacy records without the new status fields remain readable, and missing recommendation arrays no longer blank the detail page.

## Verification

- Local state-machine smoke tests covered multipart request fields, one-request deduplication, timeout recovery, legacy records, normal retry without force, and confirmed regeneration with force.
- WeChat DevTools compiled with zero workspace problems and rendered the nutrition list and latest real meal detail successfully.
- The latest backend response displayed five identified foods, including mushroom-and-pork and grilled sausage, plus three future meal menus with timing and experience content.
