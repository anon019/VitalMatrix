# Mini Program 0.3.11

## Summary

This release adapts the mini-program poster flow to the server-rendered `nutrition-poster-v9` contract. Poster typography, nutrition numbers, conclusions, and future meals remain baked into the server image; the mini program only controls eligibility, signed-URL freshness, complete-ratio display, saving, and user-facing status.

## Poster behavior

- Poster generation stays disabled until `recommendation_status` is `completed`.
- Opening an existing poster calls the ordinary poster endpoint again so the app receives a fresh short-lived signed URL without forcing a new AI generation.
- `generated=false` is handled as a successful cache hit.
- Confirmed regeneration is the only path that sends `force=true`.
- `content_digest` remounts the image after content changes, while `layout_version` is visible in the preview header for diagnosis.
- `verified_metrics` is retained for the image accessibility description and is not rendered as another nutrition panel.

## Display and saving

- The poster remains a single server image displayed with `mode="widthFix"`; no fixed 896×1200 dimensions, `aspectFill`, crop, overlay, or Canvas redraw is used.
- A 3:4 loading placeholder reduces layout shift without changing the poster's natural dimensions.
- The preview is vertically scrollable and the action footer reserves the device safe area.
- Saving downloads the original `poster_url` and writes that file directly to the photo album without secondary compression.

## Signed URLs and errors

- A failed displayed URL triggers one ordinary, non-force poster request to obtain a new signature.
- A 403 while saving refreshes the signed URL once and retries the original-file download.
- Backend messages from HTTP 422, 429, and 502 are shown as returned instead of being collapsed into a generic quota message.

## Verification

- JavaScript syntax and repository whitespace checks.
- Poster state-machine coverage for recommendation gating, cached generation, content-digest remounting, signed-URL refresh, and force separation.
- WeChat DevTools compiled with zero project problems and loaded a real cached `nutrition-poster-v9` response with `generated=false`.
- The real poster rendered as one uncropped 3:4 `widthFix` image; its loading placeholder cleared, and the save/share/regenerate footer remained outside the image with safe-area spacing.
